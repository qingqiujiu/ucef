# OpenCode Agent 配置

## 默认角色

`ucef-java-chain` 是主分析者：识别本次分析入口和实际环境，使用 `index-mcp` 理解一个或多个只读源码项目，使用 `obsidian-mcp` 维护全局笔记、图形和断点；仅在当前结论确实依赖数据库事实时加载 `padb`。

`ucef-probe` 是主动使用的源码子任务：每次只用 `index-mcp` 回答一个独立问题，不写 Obsidian，不维护全局状态。多个互不依赖的高价值问题可以并行委派。

## 权限

主 Agent 使用：

```yaml
permission: allow
```

全权限用于适配真实环境中的 MCP、Skill、Obsidian CLI 和子 Agent，避免长链路被反复授权打断；它不授权修改源码、写业务数据库或变更生产配置。源码和数据库由提示词保持只读，写入只发生在用户确认的 Obsidian 分析位置。

Probe 继续只允许 `skill` 与 `index-mcp_*`，不能写笔记或继续委派。Skill 按能力选择工具，不依赖某个固定方法名，也不需要自定义 `ucef.ts`。

## 工作方式

1. 确定名称明确的唯一分析入口和实际 Obsidian 写入位置；
2. 通过 `index-mcp` 识别实际可用项目，为本次选择一个或多个源项目；有歧义时询问用户；
3. 已有分析从入口链接的调查状态恢复，新分析创建同主题入口和状态；
4. 为可独立验证的源码问题主动委派 Probe，主 Agent 继续维护全局主线；
5. 源码无法确认且数据库事实会改变结论时，按需加载 `padb`；
6. 理解形成后局部更新正式笔记与调查状态并完成自检；
7. 根据内容生成真正有解释力的图，在切换焦点或中断前写清下一步准确入口。

不创建Planner/Block/Finalizer队列，不提交业务实体，不运行覆盖率评分，不生成HTML站点。
