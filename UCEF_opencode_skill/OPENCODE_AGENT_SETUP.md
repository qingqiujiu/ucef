# OpenCode Agent 配置

## 默认角色

`ucef-java-chain` 是主分析者：识别本次分析入口和实际环境，使用 `index-mcp` 理解一个或多个只读源码项目，使用 `obsidian-mcp` 维护全局笔记、图形和断点；仅在当前结论确实依赖数据库事实时加载 `padb`。

`ucef-probe` 是主动使用的源码子任务：每次只用 `index-mcp` 回答一个独立问题，不写 Obsidian，不维护全局状态。多个互不依赖的高价值问题可以并行委派。

## 权限

主 Agent 使用：

```yaml
permission: allow
```

全权限用于适配真实环境中的 MCP、Skill、Obsidian CLI 和子 Agent，避免长链路被反复授权打断；它不授权修改源码、写业务数据库或变更生产配置。源码和数据库由提示词保持只读，写入只发生在用户确认的 Obsidian 分析位置。

Probe 继续只允许 `skill` 与 `index-mcp_*`，不能写笔记或继续委派。Skill 按能力选择工具，不依赖某个固定方法名，也不需要自定义 `ucef.ts`。

## 工作方式

1. 确定名称明确的唯一分析入口和实际 Obsidian 写入位置；
2. 通过 `index-mcp` 识别实际可用项目，为本次选择一个或多个源项目；有歧义时询问用户；
3. 已有分析从链路封面链接的调查状态恢复；若项目陌生、范围宽泛或没有可信入口，先做有边界的初始扫描，更新探索地图，再决定提升哪条候选链路；
4. 明确新链路创建或更新业务地图、链路封面和状态。用户未指定且无既有布局时按“业务域/链路/当前链路”组织；可行动候选或第一条真实链路出现时就建立业务地图；
5. 遇到历史对象时按项目和完整符号检索、核验版本，并区分稳定语义与当前链路语境；来源快照变化时只标记受影响内容为“需复验”，不重扫项目；
6. 为可独立验证的源码问题主动委派 Probe，主 Agent 继续维护全局主线；
7. 源码无法确认且数据库事实会改变结论时，按需加载 `padb`；
8. 理解形成后局部更新正式笔记、业务地图演化记录与调查状态并完成自检；
9. 根据内容生成真正有解释力的图；交付且证据足够时至少维护一张主图，其他图不凑数量。封面需要让读者找到目的、边界、状态、来源快照、主图、未知项和下钻入口；在切换焦点或中断前写清下一步准确入口。

不创建 Planner/Block/Finalizer 队列，不提交业务实体，不运行覆盖率评分，不生成 HTML 站点。可选 Obsidian CSS 只负责外观，不参与推理、状态或完成判断。
