# MCP 调用策略

UCEF 直接使用现成 `index-mcp` 与 `obsidian-mcp`。实际工具名称由安装环境决定；按下面的能力选择对应调用，不猜测不存在的工具，也不阅读 MCP 实现脚本来学习用法。

## index-mcp

### 从业务问题到源码

先用最明确的入口、业务词、接口、消息、任务或已知符号缩小范围。获得候选后，优先按以下方式定向展开：

1. 获取精确符号定义和方法体；
2. 查找调用者，确认它怎样进入当前业务；
3. 查找被调用者，确认它把业务推进到哪里；
4. 查找实现、重写和绑定关系，避免只看到接口或默认实现；
5. 查找字段引用和赋值位置，追踪重要字段变化；
6. 仅在符号检索不足时使用文本搜索补充线索；
7. 跨项目时携带项目/模块范围，避免同名符号混淆。

每次请求只拿当前问题所需的定义、引用或代码区段。不要一次拉取整个文件、完整调用图库或大量无关搜索结果。

### 结果处理

区分定义、引用、可能调用和已确认调用。接口存在多个实现时，继续寻找选择条件和调用上下文；无法确认实际命中时保留候选，不凭名称判断。

证据引用至少包含可重新定位的项目、相对路径、符号/方法签名，以及可用时的行号。把代码含义写入Obsidian，不把大段索引结果原样复制进去。

## obsidian-mcp

### 恢复

先查找并读取 `调查状态.md`，再读取 `分析首页.md` 和当前焦点直接链接的笔记。优先按标题、块 ID 或 Wikilink读取局部内容，不遍历整个 Vault。

### 创建与更新

- 创建前先搜索，避免同一业务对象出现多个近义笔记。
- 笔记较小时可以整体创建；已有长笔记优先按标题或块局部替换、插入或追加。
- 关键问题、结论、证据、字段和方法使用稳定块 ID，标题可以随着理解改善而修改。
- 每次局部更新同时维护必要的正向链接；利用反向链接发现受影响笔记。
- 结论被推翻时保留变更说明，不静默删除旧语义。

### 图形

使用Obsidian支持的Mermaid语法生成时序图、流程图、状态图、ER图和关系图。复杂自由布局可使用已有Canvas能力。图旁保留文字结论、未知项和可点击Wikilink，因为图本身不承担唯一导航职责。

### 控制上下文

只读取当前需要的笔记和区块。更新完成后不立即全文重读验证；仅在工具返回冲突、目标不存在、更新范围不确定或阶段性交付时复查。

## MCP失败

工具不可用或返回不确定结果时，先缩小调用范围并重试一次。仍失败则记录受阻点和下一步，不循环尝试、不改写MCP脚本，也不退回旧版UCEF运行时。
