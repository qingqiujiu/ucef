# UCEF 仓库分析约束

- 源项目是只读事实来源，通过 `index-mcp` 定向检索，不修改源码。
- 不以当前工作目录判断分析位置或源码范围；每次挖掘使用名称明确的唯一入口，并在入口记录一个或多个实际源项目的标识、根目录、版本和业务职责。
- 分析笔记和持久记忆写入 Obsidian；开始长时间分析前确认实际可写，MCP 只读时使用已有 Obsidian Skill/CLI，均不可写则停止并报告阻塞。
- 仅当源码不足且数据库事实会改变结论时加载已有 `padb` Skill；查询默认只读、最小范围并脱敏。
- 业务目的、行为、分支原因、数据含义和结果始终优先于框架机制。
- 重建业务全链路，把每个重要字段追到最终消费或明确的未知断点。
- 主链中的方法提供稳定 Obsidian 下钻入口，但不要把整个仓库编成方法目录。
- 只有底层事实支持时才生成图；完整链路进入交付且证据足够时至少有一张主图，其他图形按解释价值选择，不凑数量或类型。
- 理解发生实质变化或准备中断时更新 `调查状态.md`；恢复时从状态继续，不重新扫描。
- 正式内容可以由用户移动或改写；每篇内容链接回唯一分析入口，调查状态只保存恢复指针，不根据旧状态覆盖正式笔记。
- 用户未指定且没有既有布局时，默认按“业务域/链路/当前链路”组织；第二条链路出现时再建业务地图，每条链路保持独立入口与状态，文件夹不作为恢复依据。
- 遇到历史方法、字段或模块时，按“源项目标识 + 完整符号”检索并核验版本；公共笔记只记录稳定语义，当前链路单独解释调用语境和差异，拿不准时不提前抽象。
- 主 Agent 是唯一 Obsidian 写入者；主动使用 Probe 调查可独立验证的源码问题，Probe 只用 `index-mcp` 并返回带项目归属的紧凑证据。
- 不使用自定义 UCEF Runtime、JSON 提交协议、覆盖率指标、SQLite 事实图或生成式 HTML。
