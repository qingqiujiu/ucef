# UCEF 1.0 Adaptive Workflow

The main model owns business reasoning. The program owns identities, storage, bounded recall, evidence validation, branch/configuration state, and deterministic HTML/SVG projections.

1. Bind an independent workspace and register each read-only Java project with a stable `source_id`.
2. Register a concrete Scenario with an entry, business question, expected outcome, and named P0 fields.
3. Start or resume its adaptive exploration session; do not create a planner, task queue, fixed BusinessBlocks, or a finalizer.
4. Use semantic Java-index tools directly. Follow the business main line, and deepen only where a decision, significant field change, state transition, external boundary, persistence effect, failure, or asynchronous handoff matters.
5. Persist a concise semantic milestone when a meaningful understanding has formed. Several related code lookups can produce one milestone; a lookup without an important new fact needs no write.
6. Retrieve only a bounded scenario digest and facts related to the active field, method, decision, module, or configuration key. Existing shared entities may be reused across scenarios.
7. Preserve all real branch alternatives without inventing a Cartesian decision tree. Until a trusted production lookup exists, mark the configuration `CONFIG_UNRESOLVED` and avoid claiming an active route.
8. Trace P0 fields from request through semantic transformations, decisions, database columns, outbound requests, and consumed responses. Collapse ordinary copies; summarize P1/P2 boundaries proportionately.
9. Let the runtime rebuild cross-linked scenario, system, module, decision, field, and table pages from the same facts. Components and diagrams appear only when supporting facts exist.
10. Finish when the user’s business question is answered, marginal benefit is low, the agreed budget is reached, or a permission boundary blocks further work. Publish explicit gaps rather than speculative claims.

Legacy Work Unit, direct scheduler, checkpoint, and result-import commands are retained only for existing workspaces.
